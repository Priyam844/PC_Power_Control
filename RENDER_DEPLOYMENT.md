# Render deployment values

## Using `render.yaml` (recommended)

Create the service with **New → Blueprint** and select this repository and `main`.

Render creates:

| Setting | Value |
| --- | --- |
| Service name | `pc-power-control` |
| Region | `singapore` |
| Plan | `free` |
| Root Directory | Leave empty/repository root |
| Python version | `3.12.10` |
| Build command | `pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate --noinput` |
| Start command | `python -m gunicorn wsgi:application --bind 0.0.0.0:$PORT` |
| Health check path | `/health/` |

The repository root includes `requirements.txt`, `manage.py`, `wsgi.py`, and `.python-version` shims. Do not set Root Directory to `backend` when using these commands.

## Values you must provide

Render prompts for only one value when creating the Blueprint:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | Supabase **Transaction pooler** URL below |

```text
postgresql://postgres.xetjedgmyhzatjubksrk:<URL_ENCODED_SUPABASE_DB_PASSWORD>@aws-1-ap-southeast-2.pooler.supabase.com:6543/postgres?sslmode=require
```

Replace `<URL_ENCODED_SUPABASE_DB_PASSWORD>` with the Supabase database password. If the password contains special characters, URL-encode them. Use port `6543` (Transaction pooler). Do **not** use port `5432` Session pooler or the Direct connection.

Do not put the real password in this file, Git, firmware, or chat.

## Values Render provides automatically

| Variable | What to do |
| --- | --- |
| `PYTHON_VERSION` | `3.12.10`; also set by `.python-version` and `render.yaml` |
| `DJANGO_SECRET_KEY` | Generated by `render.yaml`; no manual value needed |
| `DEBUG` | Set to `0` by `render.yaml` |
| `RENDER_EXTERNAL_HOSTNAME` | Provided by Render; settings use it for `ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS` |
| `PORT` | Provided by Render; the start command uses it |

Do not set `ENABLE_STATIC_DEV_USER` in production. Do not create a Render Postgres database; this project uses Supabase.

## If creating the service manually

Click **New → Web Service**, not **Blueprint**. Leave **Root Directory** empty, then use the build command, start command, Python version, health check path, and environment variables from this file. `render.yaml` is only applied by Blueprint services; a manually created service ignores it.

Set these environment variables:

| Variable | Value |
| --- | --- |
| `PYTHON_VERSION` | `3.12.10` |
| `DJANGO_SECRET_KEY` | Long random value, at least 50 characters |
| `DEBUG` | `0` |
| `DATABASE_URL` | The Supabase Transaction pooler URL above |

You can generate a secret key locally with:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

`ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS` are not required for the default `onrender.com` URL because `RENDER_EXTERNAL_HOSTNAME` is handled automatically.

## Optional custom domain

If you add a custom domain, set:

```text
ALLOWED_HOSTS=pc-power-control.onrender.com,your-domain.com
CSRF_TRUSTED_ORIGINS=https://your-domain.com
```

## Fixing the failed first build

If the Render log shows `Running build command 'pip install -r requirements.txt'` followed by `Could not open requirements file: [Errno 2] No such file or directory: 'requirements.txt'`, the service was created manually with the old default Root Directory. In the Render dashboard:

1. Open the service → **Settings** → **Build & Deploy**.
2. Set **Root Directory** to empty/repository root.
3. Set **Build Command** to the command in the first table.
4. Set **Start Command** to the command in the first table.
5. Under **Environment**, add the variables listed above, especially `DATABASE_URL`, `DEBUG`, and `DJANGO_SECRET_KEY`.
6. Save changes and deploy again.

## After deployment

1. Open `https://pc-power-control.onrender.com/health/`; it should return `{"status":"ok"}`.
2. Sign in at `/login/`. If this is a fresh database, create a staff account locally while using the same Supabase `DATABASE_URL`:

```powershell
cd backend
python manage.py create_initial_user --username <admin-user> --password "<strong-password>"
```

3. Open `/device-token/` and copy the generated token.
4. In the ESP8266 sketch, set:

```cpp
const char* const DEVICE_TOKEN = "<token-from-device-token-page>";
const char* const SERVER_BASE_URL = "https://pc-power-control.onrender.com";
```

Do not add a trailing slash to `SERVER_BASE_URL`.

## Free plan note

Render Free services may sleep after inactivity, so the first request after idle can be delayed. Device heartbeats often keep the service awake, but this is not guaranteed.
